## 用户目标与范围

个人自用，在当前账号下导入 Word、Markdown 研究材料，按账号既有读者、平台、语气生成文章与合适标题，然后进入现有编辑确认界面。公众号为主要平台，继续保留现有多平台、编辑、检查、配图、口播、历史及导出功能。不要求重新选择读者或文章形式。

新增：可持续编辑的应用内写作 Skill；划选段落后可自由输入改写要求，并可明确保存为长期 Skill 规则。用户于本轮提出此初版需求，未要求先完成一轮脱离应用的独立 Skill 打磨。

## 初版用户流程与默认值

1. 当前账号进入内容创作，导入 .docx 或 .md；保留原题材创作为次入口及已有历史。旧式 .doc 暂不解析，提示另存为 .docx。
2. 解析后可查看原文；自动沿用账号设定生成一套结构、正文与标题。不强制逐步确认结构，不要求选择三个方向。提供推荐标题与可选标题。
3. 新文章打开现有第 3 步编辑确认界面。原文与成稿分别保存，内容替换不覆盖原文。
4. 划选一段，既可使用扩写、缩写、专业一点等快捷动作，也可直接输入自己的要求。新研究稿的这些动作默认走新增自有 API 链路；原有其他功能沿原生机制。
5. 先预览改写结果，确认后替换或插入；失败、取消不覆盖现有正文。返回前校验稿件和正文快照，选区已改变时阻止误替换并提示重新选择。
6. 本次改写要求默认仅本次生效。显式点击“保存为长期规则”，预览并编辑规则后才保存到当前账号 Skill；不把所有临时要求自动写入 Skill。
7. 在账号设置中的“写作 Skill”入口可随时修改规则、恢复默认，并保留至少上一版以便恢复。保存后下一次新生成或 API 划词读取最新版本，已有成稿不自动重写。不同账号隔离。

## 应用内 Skill 与生成策略

Skill 是应用自身持久保存、可编辑的 Markdown 写作规则，不依赖用户安装 Codex 或打开另一聊天。默认规则先提炼结论、证据与限定条件，再组织公众号结构并成文。新生成及 API 划词继承当前账号 Skill；每次生成记录所用版本。

可以复用既有 JSON 结构化生成、正文流式展示、选区定位和改写结果预览。现有“三方向发散”提示词改为“有原文依据的结构”；新增调用不得编造数字、案例、引文或把相关关系写成因果。初版不提供自动训练、不自动更新规则，也不重建整套编辑器。

## 文件和数据边界

原始文件只读，提取文本独立保存；不覆盖已有文章、不修改其他项目。初版支持 .docx 正文及可提取文字、.md 文本；复杂表格、图片、脚注和修订信息不保证无损，发现解析警告须展示。文件过大或文本超出限制明确拒绝，不静默截断。具体解析库及限制由实现阶段核对后记入项目说明，不能无限放宽全站请求上限。

账号已有数据兼容、数据库迁移可重复执行。Skill、来源、生成信息按账号/稿件归属隔离。保存 Skill 不触发模型调用或消耗积分。

## 可观察验收

1. 在当前账号导入 .docx/.md，无需重复填写账号设定即能生成有标题的文章，进入现有编辑确认页；历史能重新打开原文和成稿。
2. 编辑 Skill 并保存后，下一次生成及 API 划词使用新规则，其他账号规则不变；能恢复上一版/默认。
3. 选区可接受任意文字要求，快捷改写也可用；结果仅确认后替换，选区过期、切稿、失败或取消不能误改当前稿件。
4. 临时指令不自动进入长期规则；显式保存并编辑确认后，后续调用才继承。
5. 新链路真实调用保留用量记录而不扣原积分；原生检查等旧链路的积分规则保持不变。前端和接口响应不暴露密钥。
6. 不支持格式、解析警告、过长输入及缺少 API 配置均有可操作提示，不输出伪成功、不静默丢内容。
7. 原有编辑、自动保存、预览、多平台及导出功能通过相关回归；Word/选区真实交互视觉验收仍由用户完成。
